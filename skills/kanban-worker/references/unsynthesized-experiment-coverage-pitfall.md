# Pitfall: Creating Tasks for Questions Already Answered by Unsynthesized Experiments

**Added:** 2026-06-02
**Category:** Director task creation waste
**Severity:** High — wastes worker slots on redundant experiments

## Problem

The Director's queue item classification (RESOLVED/RUNNING/DONE/NO_SOURCE/UNKNOWN) only checks:
1. `self_state.json`'s `experiments.completed` array (for RESOLVED items)
2. Running task titles (for RUNNING items)
3. Experiment ID references in queue item text (for DONE items)

It does NOT check completed-but-unsynthesized experiments. When synthesis hasn't processed recent completions, queue items that reference those experiments appear as NO_SOURCE (no experiment ID in text) or UNKNOWN (source experiment not in self_state). The Director then creates tasks for questions that are already answered.

## Example (2026-06-02)

Queue item [1]: "Confidence-gated fusion recovers 42% of hybrid failures — can we build a meta-learner that predicts when TF-IDF or semantic retrieval should be trusted?"

- Classification: NO_SOURCE (no exp_NNN ID in text)
- Created task: exp_1412 (confidence-gated fusion meta-learner)
- **But exp_1410 was already completed** (94.9% accuracy, 51.5% failure recovery) — just not yet synthesized
- Result: exp_1412 was redundant, had to reclaim + block

Queue item [3]: "Source-selection hybrid eliminates 173% of noise penalty — can we build a real-time source selector?"

- Classification: NO_SOURCE
- Created task: exp_1413 (real-time source selector)
- **But exp_1411 was already completed** (0.8553 accuracy, 0.5us latency) — just not yet synthesized
- Result: exp_1413 was redundant, had to reclaim + block

## Root Cause

The queue items were generated by synthesis v484, which ran BEFORE exp_1410 and exp_1411 completed. The synthesis worker generated follow-up questions based on partial results. But by the time the Director processed the queue, exp_1410 and exp_1411 had already answered those exact questions. The Director's classification couldn't catch this because it only checks `self_state.json` (which doesn't include unsynthesized experiments) and running task titles.

## Fix: Pre-Creation Coverage Check

Before creating tasks for queue items, cross-reference against completed task summaries (not just self_state.json):

```python
import json, re, subprocess

# Step 1: Find unsynthesized experiment IDs
done = json.load(open('/tmp/kanban_done.json'))
ss = json.load(open(os.path.expanduser('~/.hermes/self_state.json')))

done_exp_ids = set()
for t in done:
    title = t.get('title', '')
    is_synth = 'synth' in title.lower() or 'consolidat' in title.lower()
    if not is_synth:
        for m in re.finditer(r'exp_(\d+\w*)', title):
            done_exp_ids.add(f'exp_{m.group(1)}')

ss_exp_ids = set()
for e in ss.get('experiments', {}).get('completed', []):
    eid = e.get('id', '') if isinstance(e, dict) else ''
    if eid: ss_exp_ids.add(eid)

unsynth_ids = done_exp_ids - ss_exp_ids

# Step 2: Read summaries of unsynthesized experiments
for t in done:
    title = t.get('title', '')
    for uid in unsynth_ids:
        if uid in title:
            result = subprocess.run(["hermes", "kanban", "show", t['id'], "--json"],
                                  capture_output=True, text=True, timeout=15)
            with open(f'/tmp/unsynth_{uid}.json', 'w') as f:
                f.write(result.stdout)
            break

# Step 3: Check if any queue item's question is answered by unsynthesized summaries
for item in queue_items:
    text = item['text'].lower()
    keywords = set(w for w in text.split() if len(w) > 4)
    for uid in unsynth_ids:
        try:
            d = json.load(open(f'/tmp/unsynth_{uid}.json'))
            summary = d.get('latest_summary', '').lower()
            overlap = sum(1 for w in keywords if w in summary)
            if overlap >= 3:
                print(f"SKIP: Queue item already answered by {uid}")
                # Do NOT create task
        except:
            pass
```

## Prevention

1. **Always check unsynthesized experiment summaries** before creating tasks for NO_SOURCE or UNKNOWN queue items
2. **If an unsynthesized experiment's summary addresses a queue item's question**, skip task creation — the synthesis worker will tag it RESOLVED
3. **If the unsynthesized experiment only partially addresses the question**, create a task with explicit scope narrowing (e.g., "exp_1410 covered confidence-gated fusion but didn't test edge cases with vocabulary overlap > 0.8")

## Impact

In the 2026-06-02 session, this pitfall caused 2 redundant task creations that had to be reclaimed + blocked. Without the fix, these would have wasted 2 worker slots for 20-60 minutes each (~2% capacity at 50 workers).
