# Batch Creator False Positive: Duplicate Experiments for Running Topics (Cycle #246)

## Problem

`batch_create_tasks.py` creates new experiment tasks for queue items that are ALREADY being investigated by running experiments. This wastes worker slots on duplicate work.

## Root Cause

The batch creator's coverage check has two blind spots:

1. **No source ID matching**: Queue items generated by recent synthesis cycles lack `exp_NNN` source IDs pointing to the current running experiments. The classification marks them as `NO_SOURCE` (always a candidate), even though a running experiment is investigating the same question.

2. **Weak Jaccard overlap**: The overlap check compares queue item text against running task titles using word-level Jaccard similarity (threshold 0.6). This fails when the queue item and running task title describe the same question with different wording.

## Example (Cycle #246)

Running experiment: `exp_2386: Cross-dataset few-shot adaptation — can 5-10 target-domain samples close the 14pp meta-classifier gap?`

Queue item (selected by batch creator): `[NEW from synthesis v626] Cross-dataset few-shot adaptation — can 5-10 target-domain samples close the 14pp meta-classifier gap?`

These are THE SAME QUESTION. But the batch creator created exp_2390 for it alongside the already-running exp_2386.

**4 duplicates created in Cycle #246:**
- exp_2386 (running) ↔ exp_2390 (created) — both test cross-dataset few-shot adaptation
- exp_2387 (running) ↔ exp_2391 (created) — both test isotonic calibration production-scale
- exp_2388 (running) ↔ exp_2394 (created) — both test standalone TF-IDF+LR wins
- exp_2389 (running, completed during pass) ↔ exp_2395 (created) — both test C=50.0 optimality

## Impact

- 4 worker slots wasted on duplicate experiments
- Duplicate results will need synthesis deduplication
- Minor — experiments are cheap, synthesis handles duplicates. But at scale, this wastes API budget.

## Detection

After batch task creation, compare new task titles against running task titles:

```python
import re

new_titles = [t['title'] for t in new_tasks]
running_titles = [t['title'] for t in running_tasks]

for new_t in new_titles:
    new_words = set(new_t.lower().split())
    for run_t in running_titles:
        run_words = set(run_t.lower().split())
        overlap = new_words.intersection(run_words)
        if len(overlap) > 5:  # High word overlap = likely duplicate
            print(f"DUPLICATE: '{new_t[:60]}' <-> '{run_t[:60]}' ({len(overlap)} words)")
```

## Fix Options

### Option 1: Pre-filter before batch creation (recommended)
Before running `batch_create_tasks.py`, extract the topic text from running experiment titles and exclude queue items with high topic overlap:

```python
# Extract topics from running experiments
running_topics = []
for t in running_titles:
    m = re.search(r'exp_\d+:\s*(.+)', t)
    if m:
        running_topics.append(m.group(1).lower())

# Filter queue items
for item in queue:
    text = item.get('text', str(item)).lower()
    for topic in running_topics:
        # Check if the core question overlaps
        topic_words = set(topic.split()) - stop_words
        item_words = set(text.split()) - stop_words
        if len(topic_words.intersection(item_words)) / max(len(topic_words), 1) > 0.5:
            # This queue item is already being investigated
            item['_skip'] = True
```

### Option 2: Accept duplicates (low-cost option)
If experiment API costs are low relative to worker time, accept the duplicates. The synthesis worker will merge results. This is the pragmatic choice when:
- API costs are <$0.10 per experiment
- Worker slots are abundant
- Synthesis handles deduplication

### Option 3: Semantic dedup via RAG (architectural)
Use the experiment RAG embedding server (port 9150) to check semantic similarity between queue items and running experiment titles. This catches topical overlap that word-level Jaccard misses.

## Prevention

Director should note this gap when creating tasks via batch creator. When 4+ tasks overlap with running experiments, either:
1. Reduce `--count` by the number of overlapping items
2. Post-filter the batch creator output before dispatching
3. Accept the duplicates if costs are manageable
