Title: checkpoint_manager: run git gc with a prune grace window, not --prune=now

All four gc call sites use `--prune=now`. Under concurrent sessions sharing
one checkpoint store, `--prune=now` deletes loose objects that another
session's in-flight ref still needs; the store is left with a dangling ref
and every subsequent gc aborts with rc=128 until someone hand-deletes the
ref. Observed repeatedly at ~20 concurrent sessions.

`--prune=2.hours.ago` (git's own default is 2 weeks) keeps just-written
objects safe through any realistic gc/ref race while still collecting
garbage; the extra retention is bounded and tiny.

Running in production on a ~20-concurrent-session deployment since 2026-07;
gc failures went from recurring to zero.
